# 07 实现假设、注意事项与扩展建议

这部分用于区分“当前代码确实实现了什么”和“一个完整研究系统还可以做什么”。第一次写
模型时，明确边界比堆叠更多模块更重要。

## 1. 当前实现的主要假设

### 1.1 声源是静止的

每个事件只有一个固定位置和固定方向。模型按帧输出，但训练数据没有连续运动轨迹。
因此它可用于静止或近似静止声源定位，不能据此证明对快速移动鸡只的跟踪能力。

### 1.2 每个选中源文件只产生一个事件

一个场景有 1–3 个源文件，也对应 1–3 个事件。没有在同一声源位置上安排多段间歇叫声。
如果真实鸡叫具有复杂的反复发声节奏，模拟分布仍有差距。

### 1.3 房间是长方体 ShoeBox

墙面用统一吸声材料，未模拟网笼、设备、饲料槽、鸡体散射和非均匀墙面。RT60 有随机化，
但几何仍比真实鸡舍规则。

### 1.4 阵列几何随机，但 SALSA 参考距离固定

正四面体边长在 0.12–0.24 m 随机，而特征中的相位归一化参考距离固定为 0.20 m。
这能增加几何鲁棒性，但它是近似归一化，不是针对每个场景真实麦间距精确计算。

### 1.5 场景做共同峰值归一化

四通道间相对幅度得以保留，但场景间绝对声压信息被压平。模型不能依赖绝对响度估计距离；
当前任务也没有把距离作为输出。

### 1.6 指标是项目内简化实现

当前指标适合内部迭代和同代码条件下比较，但不是官方 DCASE SELD evaluator。发表结果前
应同时使用目标基准的官方指标。

## 2. 当前代码中应特别注意的细节

### 2.1 YAML 的 `model.input_channels` 不控制实际通道

`build_components()` 使用 `extractor.output_channels` 创建模型。启用 SALSA 时为 7，关闭时
为 4。修改 `model.input_channels` 单独不会生效。

### 2.2 改特征配置后要清理或覆盖缓存

缓存检查目前主要看通道数。若 mel_bins、FFT、频率范围变化但通道数仍是 7，旧缓存形状
或含义可能不匹配。实验时应使用 `prepare_features.py --overwrite`，或换新的数据/缓存目录。

### 2.3 推理不会自动读取阈值扫描结果

校准阈值保存在 runs JSON，`infer.py` 仍使用配置的 activity threshold。部署配置需要明确
写入 0.60，或后续为推理脚本增加 `--activity-threshold` 参数。

### 2.4 续训 history 不自动拼接

恢复 checkpoint 后权重和优化状态会继续，但 `history.json` 只保存本次进程的新轮次。
如果需要完整曲线，应在启动前保留旧 history 并在结束后合并。

### 2.5 三轨写死在部分逻辑中

模型 `tracks` 可配置，但标签生成调用和 ADPIT loss 针对 3 tracks 设计。把 tracks 改为 2
或 4 不能只改 YAML，需要同步重写候选排列逻辑与测试。

### 2.6 `tanh` 不保证输出向量是单位长度

它只限制每个 xyz 坐标。评估会使用模长判活，并在算夹角时归一化方向。这是预期行为，
不要在 forward 中无条件把所有向量归一化，否则无声向量也会被放大成活动方向。

## 3. 当前性能瓶颈

改进测试集中，各类 F1 为：

| 类别 | F1 |
|---|---:|
| Healthy | 0.3883 |
| Noise | 0.1832 |
| Unhealthy | 0.4750 |

Noise 明显较弱。事件数量也不平衡：Healthy 696、Unhealthy 579、Noise 446。下一轮改进应
先分析 Noise 的混淆和空间分布，不建议立刻盲目增大模型。

## 4. 推荐的扩展顺序

### 优先级 1：建立可靠实验对照

每次实验只改一个因素，并使用独立配置和 checkpoint 目录。至少固定：

- 数据版本和 source split；
- 随机种子；
- 训练 epoch 与 early/best 选择规则；
- 阈值只在 validation 选择；
- 同一套 test 评估脚本。

优先做 3 个不同训练种子，报告均值和标准差。单次结果可能受小数据集波动影响。

### 优先级 2：解决 Noise 类

可依次尝试：

1. 统计 Noise 被错分成 Healthy 还是 Unhealthy；
2. 对训练场景做类别均衡采样；
3. 增加 Noise 原始源文件或更丰富噪声类型；
4. 对难例提高抽样概率，而不是简单复制全部 Noise；
5. 在验证集比较统一阈值与分类别阈值。

类别重采样应在场景生成或 sampler 层完成，并继续保持源文件级划分隔离。

### 优先级 3：改进数据真实性

- 多事件间歇发声；
- 移动轨迹及速度约束；
- 不同墙面材料和障碍物；
- 扩散背景噪声、风扇和设备噪声；
- 麦克风增益、时钟、相位和位置误差；
- 使用真实鸡舍 RIR 或真实四通道录音做域适配。

### 优先级 4：改进模型

在数据和评估稳定后再尝试：

- 为 Conformer 加相对位置编码；
- 在频率池化前加入注意力池化；
- 多尺度时间卷积；
- SED 与 DOA 辅助头；
- 指数滑动平均权重；
- 更严格的官方 ADPIT/SELD 实现对齐。

模型变大不一定解决仿真到真实数据的域差距，因此优先级低于数据真实性与评估规范。

## 5. 从静止定位扩展到移动定位

需要同时修改三层：

```text
仿真层：为每个声源定义 position(t)，分段渲染或使用时变 RIR
标签层：每个 100 ms 帧计算新的阵列局部单位方向
后处理：跨帧关联同一声源，输出连续轨迹
```

模型输出协议 `[time, track, class, xyz]` 本身已经包含时间维，可暂时不改；但 ADPIT 的
无固定轨道特性可能造成轨迹 ID 切换。如果任务需要“这是同一只鸡”，还需要显式跟踪或
轨道连续性损失。

## 6. 调试清单

训练异常时按这个顺序检查：

1. 一个 batch 的 features/target 形状是否正确；
2. features 是否有限值，标准化后均值和方差是否合理；
3. target 活动向量是否真为单位向量；
4. 一个活动样本能否让 loss 明显下降；
5. 模型是否输出全零或所有轨道完全重复；
6. train loss、validation loss 是否分叉；
7. F1 低是 FP 多还是 FN 多；
8. LE 差是所有类别都差，还是某一类/某些房间差；
9. 使用的 checkpoint、配置、特征缓存是否属于同一实验；
10. 阈值是否只在验证集选择。

第一次写模型时，形状错误、缓存版本和配置错配比“模型不够先进”更常见。先用一个样本、
一个 batch 和 smoke 数据把每层行为验证清楚，再扩大训练。

## 7. 建议新增的单元测试

当前已有 8 项核心测试。下一步最值得补充：

- 特征输出 `[7,64,501]` 和无 NaN；
- 标准化广播维度；
- 数据增强不改变形状；
- 1/2/3 声源 ADPIT 候选均正确；
- 阈值边界行为；
- 推理 JSON 角度范围；
- 配置继承与覆盖；
- resume 后 epoch 与学习率连续性。

测试的价值是让你敢于修改模型，而不是只在最后发现完整训练跑坏了。
